# Соглашения по написанию кода

Документ обязателен для всех сервисов и шасси. Правила здесь — следствие принятых
ADR; если правило противоречит ADR, побеждает ADR, а документ исправляется.

**Язык.** Идентификаторы, комментарии и docstring — английский. Проектная
документация (`docs/`) — русский. Причина: код читают потенциальные работодатели,
документация — ты.

---

## 1. Базовые принципы

1. **Явное лучше неявного.** Никакой магии импортов, автосканирования модулей,
   динамического создания классов.
2. **Домен ничего не знает об инфраструктуре.** Проверяется тем, что тесты домена
   выполняются без БД, брокера и сети.
3. **Ошибка должна проявляться как можно раньше** — при старте процесса, а не при
   первом запросе; в типах, а не в рантайме; в БД, а не в коде.
4. **Дублирование между сервисами допустимо, связность — нет.** Скопировать 20 строк
   лучше, чем создать общий пакет ради переиспользования домена.
5. **Код пишется под чтение.** Если решение неочевидно — комментарий объясняет
   *почему*, а не *что*.

## 2. Структура

### 2.1 Репозиторий

```
services/<name>/
  src/<name>/
    api/              роутеры, схемы запросов и ответов, зависимости FastAPI
    application/      сценарии, оркестрация, потребители событий, фоновые задачи
    domain/           сущности, значения, правила, доменные исключения, порты
    infrastructure/   репозитории, ORM-модели, клиенты, конфигурация
    cli/              команды обслуживания
  migrations/
  tests/
    unit/             без внешних зависимостей
    integration/      testcontainers
  Dockerfile
  pyproject.toml
libs/chassis/         сквозная инфраструктура (без домена)
contracts/events/     JSON Schema событий
deploy/               kustomize, argocd, локальная среда
```

### 2.2 Правила импорта между слоями

| Слой | Может импортировать | Не может |
|---|---|---|
| `domain` | стандартную библиотеку, `domain` | всё остальное, включая pydantic и SQLAlchemy |
| `application` | `domain`, порты, `chassis` | `api`, `infrastructure` (только через порты) |
| `infrastructure` | `domain`, `application` (порты), `chassis` | `api` |
| `api` | `application`, `domain`, `chassis` | `infrastructure` напрямую |

Правило проверяется линтером (`ruff` + `import-linter`), а не договорённостью.

**Категорически запрещено:** импорт из `services/<other>/`. Между сервисами существуют
только события и HTTP-контракты.

## 3. Именование

| Сущность | Правило | Пример |
|---|---|---|
| Модули и пакеты | `snake_case`, существительное | `working_hours.py` |
| Классы | `PascalCase` | `BookingRepository` |
| Функции и переменные | `snake_case` | `calculate_slots` |
| Константы | `UPPER_SNAKE` | `DEFAULT_GRID_STEP_MINUTES` |
| Булевы | префикс `is_`, `has_`, `can_` | `is_active` |
| Асинхронные функции | без суффикса `_async` | `async def get_booking` |
| Таблицы БД | `snake_case`, множественное число | `schedule_exceptions` |
| Колонки времени | суффикс `_at` (момент), `_on` (дата) | `created_at`, `effective_on` |
| Денежные поля | суффикс `_amount` + отдельная `currency` | `price_amount` |
| Топики Kafka | `<service>.<aggregate>` | `booking.bookings` |
| События | `PascalCase`, прошедшее время | `BookingConfirmed` |
| Метрики | `<service>_<subject>_<unit>` | `booking_holds_expired_total` |
| Фикстуры pytest | существительное без `test_` | `booking_factory` |

**Запрещённые имена:** `data`, `info`, `obj`, `manager`, `helper`, `utils` в качестве
имени модуля или класса. Модуль `utils.py` не создаётся — функция кладётся туда, где
она применяется по смыслу.

## 4. Типизация

- `mypy` в режиме `strict`, без исключений по модулям.
- `Any` запрещён. Если тип действительно неизвестен — `object` + явное сужение.
- `# type: ignore` допустим только с кодом ошибки и комментарием-причиной:
  `# type: ignore[arg-type]  # stripe-python has no stubs for this call`.
- Публичные функции аннотируются полностью, включая возврат `None`.
- Порты домена описываются через `typing.Protocol`, не через абстрактные классы.
- Идентификаторы — `NewType`, а не голый `UUID`:

```python
BookingId = NewType("BookingId", UUID)
SpecialistId = NewType("SpecialistId", UUID)
```

Причина: перепутанные местами идентификаторы — самая частая ошибка в системе, где
всё является UUID, и типы ловят её бесплатно.

---

## 5. Модели данных: три раздельных представления

Одна и та же сущность существует в трёх видах, и они **не смешиваются**:

| Вид | Где | Чем является |
|---|---|---|
| Схема API | `api/schemas/` | pydantic-модель запроса или ответа |
| Доменная сущность | `domain/` | `@dataclass(frozen=True, slots=True)` без зависимостей |
| ORM-модель | `infrastructure/db/models.py` | декларативный класс SQLAlchemy |

Преобразование выполняется явно в мапперах. Возвращать ORM-модель из роутера
запрещено — это связывает контракт API со схемой БД.

Доменная сущность неизменяема; изменение состояния возвращает новый объект либо
выполняется методом агрегата, возвращающим доменное событие.

---

## 6. Домен

- Никаких обращений к БД, сети, `datetime.now()` и генерации UUID внутри домена:
  время и идентификаторы передаются аргументами. Иначе домен не тестируется
  детерминированно.
- Бизнес-правила — методы агрегата, а не функции в сервисном слое.
- Доменные исключения наследуются от `DomainError`, каждое имеет код из каталога:

```python
class SlotAlreadyTaken(DomainError):
    code = "slot_taken"
    http_status = 409
```

- Валидация значений — в конструкторах value-объектов, а не в сценариях.

---

## 7. Слой сценариев (`application`)

- Один сценарий — один класс или функция с единственным публичным методом.
- Транзакция начинается и заканчивается **в сценарии**, не в репозитории и не в
  роутере.
- В одной транзакции с изменением состояния пишется событие в `outbox`. Публикация
  напрямую в брокер из сценария запрещена (ADR-0005).
- Сценарий не знает о HTTP: не принимает `Request`, не возвращает `Response`,
  не оперирует статус-кодами.
- Зависимости передаются через конструктор, а не импортируются глобально.

---

## 8. Инфраструктура и работа с БД

- Только асинхронный SQLAlchemy 2.x, стиль `select()`. `session.query()` запрещён.
- Ленивая загрузка отключена (`lazy="raise"`). Связи загружаются явно через
  `selectinload` — иначе N+1 появляется незаметно.
- Репозиторий возвращает доменные сущности, а не ORM-модели.
- В каждом запросе фильтрация по `tenant_id` обязательна. Метод репозитория без
  `tenant_id` в сигнатуре — повод для отказа на ревью (D40).
- Сырой SQL допустим для расчёта доступности и подобных мест, где ORM мешает; он
  оформляется отдельной функцией с комментарием, зачем понадобился.
- Транзакции — через явный контекстный менеджер сессии. Автокоммит запрещён.
- Любой внешний вызов (Stripe, SMTP, HTTP) имеет таймаут. Вызов без таймаута —
  дефект.

### Миграции

- Одна миграция — одно логическое изменение, с осмысленным `slug`.
- Обязательно реализуется `downgrade`, кроме миграций данных, где это невозможно —
  там пишется комментарий с причиной.
- Политика **expand/contract**: сначала добавляем, переводим код, потом удаляем.
  Переименование колонки одним шагом запрещено (D55).
- Миграции данных — отдельными ревизиями, не вместе со схемой.

## 9. API

- Пути — существительные во множественном числе, `kebab-case`:
  `/api/v1/specialists/{id}/working-hours`.
- Версия — в пути. Ломающее изменение → новая версия (D45).
- Коды: `200`, `201` (создание), `204` (без тела), `400` (валидация),
  `401`, `403`, `404`, `409` (конфликт состояния), `422` (валидация pydantic),
  `429`, `500`.
- Ошибки — `application/problem+json` с полями `type`, `title`, `status`, `detail`,
  `code`, `trace_id` (D43).
- Списки — только курсорная пагинация, ответ `{"items": [...], "next_cursor": ...}`.
- Изменяющие операции, которые клиент может повторить, принимают заголовок
  `Idempotency-Key`.
- Ответ никогда не содержит внутренних идентификаторов чужих сервисов, ORM-полей и
  технических статусов.
- Время в API — строки RFC 3339 в UTC. Локальное время наружу не отдаётся.

---

## 10. События

- Имя — факт в прошедшем времени: `BookingConfirmed`. Исключение — команды саги
  (`PaymentVoidRequested`), они помечаются комментарием.
- Конверт и обязательные поля — по [EVENTS.md](EVENTS.md).
- Схема события лежит в `contracts/events/<Name>.v<N>.json` и проверяется на
  публикации и на потреблении.
- Потребитель — tolerant reader: неизвестные поля игнорируются, отсутствие
  необязательных не ломает обработку.
- Обработчик события идемпотентен всегда, без исключений (D18).
- Событие содержит данные, а не ссылку «сходи и получи». Потребитель не должен
  ходить в чужой сервис за деталями.

---

## 11. Ошибки, логи, телеметрия

- `except Exception` без повторного возбуждения запрещён. Проглоченное исключение —
  дефект.
- Пустой `except: pass` запрещён без исключений.
- Логи структурные, только через логгер шасси. `print` запрещён.
- **Никогда не логируются:** пароли, токены, заголовок `Authorization`, ключи Stripe,
  содержимое вебхуков целиком, персональные данные сверх идентификатора.
- Уровни: `ERROR` — требует вмешательства; `WARNING` — аномалия, с которой система
  справилась; `INFO` — значимое бизнес-событие; `DEBUG` — детали разработки.
  Ожидаемая ошибка клиента (`409`, `404`) — это не `ERROR`.
- Каждый лог внутри запроса содержит `trace_id` автоматически; вручную его
  прокидывать не нужно.
- Новая метрика заводится вместе с ответом на вопрос «какое решение я приму, увидев
  её изменение». Метрика без такого ответа не заводится.

---

## 12. Конфигурация и секреты

- Только переменные окружения через `pydantic-settings`, чтение `os.environ`
  напрямую запрещено.
- Валидация при старте, падение при неполной конфигурации (D54).
- Значения по умолчанию допустимы для локальной разработки, но **не** для секретов,
  адресов БД и внешних сервисов.
- Секреты не попадают в репозиторий в открытом виде, в логи и в сообщения об ошибках.
- Никаких переключателей поведения через переменные окружения без записи в
  документации.

---

## 13. Асинхронность и фоновые задачи

- Весь ввод-вывод асинхронный. Блокирующий вызов в корутине — дефект; при
  необходимости — `run_in_executor` с комментарием.
- `asyncio.create_task` без сохранения ссылки и обработки исключений запрещён.
- Фоновые задачи — только через планировщик шасси, с advisory lock от параллельного
  исполнения (D57).
- Задача обязана быть перезапускаемой: прерывание в любой момент не должно оставлять
  систему в противоречивом состоянии.

## 14. Тесты

- Структура файла: **Arrange → Act → Assert**, с пустыми строками между блоками.
- Имя теста описывает поведение:
  `test_create_booking_returns_409_when_slot_is_taken`.
- Один тест проверяет одно поведение. Несколько `assert` допустимы, если они
  описывают одно и то же поведение.
- **Собственный код не мокается.** Мокаются только внешние границы: Stripe, SMTP,
  Google. БД, Kafka и Redis поднимаются в testcontainers.
- Домен тестируется без инфраструктуры. Если для теста правила нужна БД — правило
  лежит не в том слое.
- Обязательные тесты для каждого эндпоинта: отсутствие прав, чужой тенант,
  невалидный ввод.
- Фикстуры — фабрики, а не готовые объекты: тест сам задаёт значимые для него поля.
- `time.sleep` в тестах запрещён; время подменяется, ожидание — через условие.
- Флейки не игнорируются и не отключаются: либо чинятся, либо удаляются.

## 15. Git и ревью

- Trunk-based: ветка от `main`, PR обратно в `main`, ветка живёт не дольше пары дней.
- Имя ветки: `<type>/<task-id>-<slug>`, например `feat/P4-T14-create-booking`.
- Коммит — Conventional Commits, в теле — ссылка на задачу плана:

```
feat(booking): create booking with idempotency key

Implements P4-T14. Hold is created inside a single transaction
together with the outbox record.
```

- Один PR — одна задача плана. PR, меняющий больше ~400 строк, разбивается.
- PR не мержится с красным конвейером и без тестов, перечисленных в задаче.

### Чек-лист ревью

1. Слои не нарушены, чужой сервис не импортирован.
2. Фильтрация по `tenant_id` присутствует во всех запросах.
3. Событие пишется в outbox в той же транзакции.
4. Обработчик события идемпотентен.
5. Внешние вызовы имеют таймаут.
6. Ошибки возвращаются в problem+json с доменным кодом.
7. В логах нет чувствительных данных.
8. Тесты из задачи написаны, включая межтенантный доступ.
9. Миграция обратима и не ломает работающую версию кода.
10. Документация или ADR обновлены, если решение изменилось.

## 16. Запрещённые практики

| Запрещено | Причина |
|---|---|
| Импорт между сервисами | распределённый монолит |
| Доменные типы в шасси | общий релизный цикл (D7) |
| Синхронный HTTP-вызов другого сервиса | связывание доступности |
| Публикация в брокер вне outbox | потеря атомарности |
| Бизнес-логика в роутере | невозможность тестировать без HTTP |
| ORM-модель в ответе API | контракт привязан к схеме БД |
| Проверка занятости слота только в коде | нарушение инварианта (D12) |
| Чтение кэша на пути записи | двойное бронирование (D25) |
| Наивный `datetime` без зоны | ошибки DST (D13) |
| Хранение смещения вместо IANA-зоны | сломанное расписание при переходе |
| Локальное время в БД | неоднозначность момента |
| `float` для денег | потеря точности |
| Мок собственного репозитория в интеграционном тесте | тест проверяет мок, а не систему |
| Глобальный изменяемый стейт, синглтоны | невоспроизводимые тесты |
| `TODO` без ссылки на задачу | вечный долг |
