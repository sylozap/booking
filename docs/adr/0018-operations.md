# ADR-0018: Эксплуатационные решения — манифесты, секреты, конфигурация, миграции, бэкапы, задачи, тесты, CI

- **Статус:** Принято
- **Решения:** D51–D60

## Контекст

Ревью полноты показал, что шесть эксплуатационных областей не имели решений вовсе
(бэкапы, конфигурация, секреты) либо были определены только контурно (миграции,
тестирование, CI/CD, деплой). Начинать реализацию без них означает вносить
инфраструктуру задним числом — против чего принят ADR-0009.

## Решение

| Тема | Решение | Отвергнутая альтернатива и причина |
|---|---|---|
| Манифесты | Kustomize, base + overlay на окружение | Helm — шаблонизация YAML избыточна, чарты никому не публикуются |
| Секреты | SOPS + age, зашифрованные файлы в репозитории | External Secrets — требует внешнего хранилища, локально отсутствующего |
| Ключи подписи JWT | Пара ключей в секрете; ротация с периодом перекрытия, JWKS отдаёт оба ключа | Ротация без перекрытия — одномоментный разлогин всех пользователей |
| Конфигурация | `pydantic-settings`, только переменные окружения, ConfigMap + overlay, fail-fast валидация на старте | Конфиг-файлы в образе — образ перестаёт быть переносимым между окружениями |
| Миграции | Отдельный Job, запускаемый ArgoCD PreSync-хуком; политика expand/contract; ломающие миграции запрещены | Миграция в entrypoint приложения — гонка между репликами при rolling update |
| Бэкапы | Оператор CloudNativePG, WAL-архив в MinIO, плановая проверка восстановления | `pg_dump` в CronJob — нет PITR, восстановление не проверяется |
| Фоновые задачи | Отдельный Deployment на сервис; планировщик внутри процесса; защита от параллельного исполнения через advisory lock PostgreSQL | k8s CronJob — минимальный интервал в одну минуту слишком груб для истечения удержаний |
| Окружения | `dev` и `prod` как namespace одного кластера, разные overlay | Отдельные кластеры — ресурсы локальной машины |
| Тестирование | Пирамида: unit на домен без инфраструктуры, интеграционные на testcontainers, contract-тесты на JSON Schema событий с обеих сторон, e2e только на сагу оплаты | E2E-тяжёлая стратегия — медленно, хрупко, плохо локализует дефект |
| CI | Триггеры по путям монорепозитория; тег образа = git sha; CI коммитит новый тег в манифесты | ArgoCD Image Updater — меньше контроля и хуже аудируемость |
| Ветвление | Trunk-based, PR в `main`, обязательные проверки | git-flow — избыточен для одного разработчика |

## Последствия

**Приобретаем:** воспроизводимое из репозитория состояние кластера; проверяемое
восстановление данных; отсутствие гонок при миграциях и фоновых задачах; контрактные
тесты, ловящие несовместимость событий до деплоя.

**Платим:** SOPS требует хранить ключ age вне репозитория — его потеря делает секреты
нечитаемыми; CloudNativePG и MinIO добавляют ощутимую нагрузку на локальный кластер;
политика expand/contract запрещает «просто переименовать колонку» и всегда требует
двух шагов; advisory lock привязывает планировщик к доступности PostgreSQL.
