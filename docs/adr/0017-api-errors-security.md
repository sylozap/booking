# ADR-0017: Контракт API, обработка ошибок и базовая безопасность

- **Статус:** Принято
- **Решения:** D43–D50

## Контекст

Эндпоинты определены, но формат ошибок, пагинация, политика версионирования и базовые
меры безопасности не были зафиксированы. Без единого решения каждый сервис изобретёт
собственный формат, а клиент не сможет обрабатывать ошибки единообразно.

## Решение

| Тема | Решение |
|---|---|
| Формат ошибок | RFC 9457 `application/problem+json`; каталог доменных кодов (`slot_taken`, `hold_expired`, `outside_working_hours`, …); маппинг «доменное исключение → код → HTTP-статус» в одном месте шасси |
| Пагинация | Курсорная, лимит по умолчанию 50, максимум 200 |
| Версионирование | `/api/v1` в пути; ломающее изменение — только новая версия |
| Пароли | argon2id |
| Rate limiting | На Ingress по IP; отдельный жёсткий лимит на `/auth/login` по email |
| Аудит | Таблица `audit_log` в `identity` для операций с правами и ролями; бизнес-действия уже покрыты outbox |
| Персональные данные | Удаление аккаунта = анонимизация пользователя; брони и платежи сохраняются |
| Логи | Список чувствительных полей в шасси, маскирование до записи |

## Рассмотренные альтернативы

**Собственный формат ошибок.** Отвергнуто: RFC 9457 стандартен, расширяем полем
`code` и поддерживается инструментами.

**Пагинация по `offset`/`limit`.** Проще и позволяет прыгать на произвольную страницу.
Отвергнуто для списков броней: при вставках и удалениях страницы «съезжают», а
глубокий offset деградирует по времени.

**Версионирование заголовком или media type.** Отвергнуто: путь виден в логах,
трассировке и метриках без дополнительной разметки.

**bcrypt.** Отвергнуто: argon2id устойчивее к атакам на специализированном железе.

**Физическое удаление пользователя.** Отвергнуто: разрушает финансовые записи и
историю броней, которые не могут быть удалены вместе с профилем.

## Последствия

**Приобретаем:** единообразную обработку ошибок на клиенте; стабильную пагинацию;
базовую защиту учётных записей.

**Платим:** курсорная пагинация не позволяет перейти на произвольную страницу;
анонимизация вместо удаления требует отдельной проверки, что PII не остались в
логах и уведомлениях; каталог кодов ошибок нужно поддерживать в актуальном состоянии.
