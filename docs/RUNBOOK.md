## Ключ age и секреты SOPS

Секреты хранятся в репозитории зашифрованными (D52, [ADR-0018](adr/0018-operations.md)).
Расшифровать их может только владелец приватного ключа age.

### Где что лежит

| Что | Где | В репозитории |
|---|---|---|
| Приватный ключ age | `~/.config/sops/age/keys.txt`, права `600` | **нет и никогда** |
| Публичный ключ | `.sops.yaml`, поле `age:` | да |
| Зашифрованные секреты | `deploy/k8s/base/secrets/*.enc.yaml` | да |
| Копия ключа для кластера | Secret `sops-age` в namespace `argocd` | нет |

Шифруются только значения: `encrypted_regex` в `.sops.yaml` оставляет ключи, имена и
метаданные открытыми. Поэтому по диффу видно, какой секрет изменился, и ревьюер может
проверить корректность манифеста, не имея ключа. Комментарии **внутри** `stringData`
шифруются вместе со значениями — пояснения пишутся выше блока.

### Первичная настройка на новой машине

```bash
make tools          # инструменты, включая sops, age и ksops
make secrets-key    # создаст ключ, если его нет, и напечатает публичную часть
```

Если ключ создаётся заново, а не переносится, публичную часть надо вписать в
`.sops.yaml` и перешифровать все существующие файлы:

```bash
sops updatekeys deploy/k8s/base/secrets/placeholder.enc.yaml
```

### Перенос ключа на другую машину

Ключ — это файл. Переносится любым способом, который не оставляет его копию в чужих
руках: менеджер паролей, зашифрованный носитель. Не через почту, чат и не через
репозиторий.

```bash
mkdir -p ~/.config/sops/age
install -m 600 /path/to/keys.txt ~/.config/sops/age/keys.txt
```

### Как секрет попадает в кластер расшифрованным

1. `make secrets-push` кладёт приватный ключ в Secret `sops-age` (namespace `argocd`).
2. `argocd-repo-server` монтирует его в `/.config/sops/age/keys.txt` и несёт плагин
   KSOPS, установленный init-контейнером.
3. ArgoCD рендерит `deploy/k8s/base/secrets` через `kustomize build` с
   `--enable-alpha-plugins --enable-exec`; KSOPS расшифровывает файлы на лету.
4. В кластер уезжает обычный `Secret` — расшифрованный. В git он остаётся зашифрованным.

Расшифровка происходит **только** там, где рендерятся манифесты. В CI ключа нет и быть
не должно, поэтому `deploy/k8s/base/secrets` намеренно не подключён ни к одному overlay:
иначе `kustomize build` в пайплайне требовал бы приватный ключ.

### Работа с секретом

```bash
make secrets-edit FILE=deploy/k8s/base/secrets/placeholder.enc.yaml  # правка на месте
make secrets-build                                                   # локальный рендер
sops --decrypt deploy/k8s/base/secrets/placeholder.enc.yaml          # только посмотреть
```

Расшифрованную копию на диск не сохранять. `.gitignore` перехватывает `*.dec.yaml` и
`keys.txt`, но это страховка, а не разрешение.

### Ротация ключа

Плановая — раз в год, внеплановая — немедленно при любом подозрении на утечку.

```bash
age-keygen -o ~/.config/sops/age/keys-new.txt
age-keygen -y ~/.config/sops/age/keys-new.txt          # публичная часть
# добавить новый публичный ключ в .sops.yaml, СТАРЫЙ ПОКА НЕ УДАЛЯТЬ
sops updatekeys deploy/k8s/base/secrets/*.enc.yaml     # перешифровать на оба ключа
# заменить keys.txt новым файлом, затем:
make secrets-push
kubectl --context kind-booking --namespace argocd rollout restart deployment/argocd-repo-server
# убедиться, что синхронизация проходит, и только теперь убрать старый ключ из .sops.yaml
sops updatekeys deploy/k8s/base/secrets/*.enc.yaml
```

Период перекрытия обязателен: если удалить старый ключ до того, как новый доказал
работоспособность, единственная копия рабочего ключа окажется удалённой из `.sops.yaml`,
а файлы — зашифрованными на ключ, который ещё не проверен.

### Ключ потерян

Восстановить содержимое зашифрованных файлов **невозможно**. Это не проблема ключа —
это то, за что заплачено при выборе SOPS ([ADR-0018](adr/0018-operations.md), раздел
«Платим»). Порядок действий:

1. Сгенерировать новый ключ, вписать публичную часть в `.sops.yaml`.
2. Все `*.enc.yaml` создать заново из первоисточников: Stripe — в дашборде Stripe,
   Google OAuth — в Google Cloud Console, ключи подписи JWT — сгенерировать новую пару.
3. Ключи подписи JWT после замены инвалидируют все выданные токены: пользователи
   разлогинятся. Перекрытия здесь нет, потому что старый ключ нечитаем.
4. `make secrets-push` и перезапуск `argocd-repo-server`.

Отсюда правило: ключ хранится минимум в двух местах, и хотя бы одно из них — не эта
машина.
